### Findings

| id | verdict | finding | blast | effort | conf |
|----|---------|---------|-------|--------|------|
| A-CLS-1 | F1 | `mission close` refuses on its own `.factory/claim`. The Factory writes that file, then counts it as "dirty outside the mission folder" and blocks the close. No part ships a `.gitignore` line for it, so on a fresh project `mission close` can never succeed until the human works out that the blocker is a Factory-generated file. `/opt/ed/ivy` only escapes because its `.gitignore` was hand-edited. Fix: have the dirty check ignore `.factory/claim`, or ship the ignore line from a part | wide | S | high |
| A-DOG-1 | F2 | Snippet dedupe is exact-string, so a project with a hand-written `## Important Files` gets duplicates. igs `agents.md` now reads `- Terminology: \`docs/terminology.md\`` and `- Roadmap: \`docs/roadmap.md\`` immediately followed by `- Terminology: @docs/terminology.md` and `- Roadmap: @docs/roadmap.md` — the same two files listed twice in the same section, in two notations. Every project that already documents its own important files will hit this on first install | wide | M | high |
| A-HND-2 | F3 | `handoffs/W5.md` has no `Acceptance:` line at all. The template makes `Step`, `Done`, `Acceptance` mandatory, and A-DOG-1/A-DOG-2 were W5's to call — their verdicts exist only as prose. The optional-field rule was followed; a required field was dropped | narrow | S | high |
| - | F4 | `--skip` is wired only to `update`. `src/cli.ts:38-58` passes it in the `update` branch and nowhere else, so `install --skip a,b`, `uninstall --skip …` and `status --skip …` accept the flag and ignore it silently. `AGENTS.md:97` documents it for all four commands (`install \| uninstall \| status \| update [project] [--skip a,b]`); `README.md:36` lists it only on `update` and is right. ### Tooling

There is no `.factory/factory.yaml` in this repo, so neither `e2e.ready` nor `verify` exists and both
gatekeepers improvised — three separate handoffs say so. Add one with `ready: ["bun x tsc --noEmit"]`
and an `e2e` block whose `ready` builds a throwaway repo and walks `mission new --stub` -> `open
--dry-run` -> `step` -> `close`; that single recipe would have caught F1 (`mission close` blocked by
`.factory/claim`) on the first run instead of the last. Pair it with a `--yes` flag on `install` and
`uninstall`, which W1, W3 and the Orchestrator all asked for — without it every check of the two
most important commands in the product needs a hand-timed pty and arrow-key choreography.
