## codegraph: igs hand wiring vs what `parts/codegraph` would write

`${codegraph}` resolves through `src/core/recipes.ts` `resolvePart`: `~/.factory/config.yaml` `vars` beats the part's own `vars`. On this machine `~/.factory/config.yaml` is `vars: { codegraph: codegraph }`, so `${codegraph}` -> `codegraph` and everything below matches igs' hand wiring except where noted. Without that config the part's default `npx -y @colbymchenry/codegraph@1.6.0` applies and the first word becomes the command, the rest lead the args.

Resolved and written into a scratch dir seeded with copies of igs' two JSON files (`/tmp/w5sim`, igs never touched):

1. `.mcp.json` → `mcpServers.codegraph`
   - igs:  `{"type":"stdio","command":"codegraph","args":["serve","--mcp"]}`

   - Single difference: the part drops `"type": "stdio"`. `part.yaml` `mcp.config` has no `type` key and `injectMcp` replaces the whole server object, so installing would delete that line. Claude Code defaults an entry with `command` to stdio, so this is cosmetic; add `type: stdio` to `parts/codegraph/part.yaml` `mcp.config` if you want the two byte-identical.
   - Unconfigured machine instead gets `{"command":"npx","args":["-y","@colbymchenry/codegraph@1.6.0","serve","--mcp"]}`.

2. UserPromptSubmit hook — different file and different command, so installing ADDS a second hook rather than replacing igs'.
